## 1. What v0.2 delivers

v0.2 closes the gap between the rich v0.1 no-install prototype and the React production app, and adds
the thing the prototype never had: **a different dashboard for every RBAC tier**. It is a hosted web
application — users open a URL, nothing to install.

### 1.1 Feature parity restored (all nine)
Dashboard, Projects, Sprint Board, Tasks, Documentation, Meeting Intelligence, Communication,
Innovation Pipeline and Reports are all present again as React pages wired to the API — plus the
AI Assistant and Notes. The sidebar shows each tier only the items it is permitted to use.

### 1.2 Five DISTINCT tier dashboards
Each tier gets what it actually needs, not a shared layout:

| Tier | Role | Dashboard focus |
|------|------|-----------------|
| 1 | Final Leader (MD) | **Outcomes only** — portfolio health, overall delivery %, at-risk projects, critical escalations, Team Alpha vs Apex performance, AI executive briefing, one-click board PDF. No ticket controls. |
| 2 | Squad Leader (admin) | **Department-wide control** — open/blocked/overdue/unassigned counts, assign unassigned work to any engineer in-place, workload-per-engineer, active sprints, quick links to manage projects/tasks. |
| 3 | Team Captain | **Their team only** — team open/blocked/in-review/completion, manage (assign + status) their team's tasks, team roster workload, blockers to escalate. |
| 4 | Software Engineer | **My work only** — my open/in-progress/blocked/due-this-week, my task list with self-service status moves, my current sprint, AI focus prompt. |
| 5 | General Firm | **Read-only + a note** — plain-language project-progress cards (no tickets/owners/internals), and a box to leave a note for the IT division. |

### 1.3 Fluid, reactive design system
`frontend/src/styles.css` was rewritten to restore the original identity — deep navy `#071B33` +
signature lime `#ADD135` — as a modern, fluid system: `clamp()` typography/spacing, auto-fit grids
that reflow on any screen, hover/focus micro-interactions, animated KPI tiles, progress bars and a
team bar chart. The login page was re-aligned into a balanced two-pane shell. `prefers-reduced-motion`
is respected.

## 2. Backend additions (production-ready, RBAC-guarded)

New routes mounted in `server.ts`, each behind `authMiddleware` + a permission guard:

- `GET /api/users` — directory for assignment dropdowns & workload widgets (`task:view`; safe fields only — no password hash; the read-only General Firm tier cannot enumerate staff).
- `GET/POST /api/documents` — documentation centre (`doc:view` / `doc:manage`).
- `GET/POST /api/messages` — channel communication (`comm:participate`).
- `GET /api/meetings` — saved meeting packs (`ai:use`; created via `POST /api/ai/meeting`).
- `GET/POST /api/sprints` — sprints (`sprint:view` / `sprint:manage`).

The RBAC single source (`backend/src/config/rbac.ts`, mirrored in `frontend/src/config/roles.ts`)
gained `doc:view`, `doc:manage` and `comm:participate`, granted to Tiers 1–4 (never Tier 5).

The seed (`db/seed.ts`) now lays down a deterministic demo dataset: four projects across both teams
(one Amber, one Red for the leader view), two sprints, thirteen tasks spanning every status with
blocked/overdue/unassigned cases, four documents, four channel messages and a sample meeting — so
every dashboard has real material on first run.

## 3. Verification status

- **Type safety:** `npx tsc --noEmit` passes clean for **both** `frontend/` and `backend/`.
- **Static review:** the JWT payload, env contract and every new route/seed field were checked against
  `prisma/schema.prisma` and the frontend response shapes — all aligned.
- **Runtime:** a live run requires the platform-native `esbuild`/Prisma binaries, so it is performed on
  the developer machine (see §4), not in the build sandbox.

## 4. How to run (developer machine)

```
# Backend
cd backend
npm install
npm run db:setup     # prisma generate + db push + seed
npm run dev          # API on http://localhost:4000

# Frontend (separate terminal)
cd frontend
npm install
npm run dev          # app on http://localhost:5173 (proxies /api to :4000)
```

Sign in with any demo account (see the login page). The Anthropic key lives only in `backend/.env`
(git-ignored); without it the AI features run in a safe fallback mode.
